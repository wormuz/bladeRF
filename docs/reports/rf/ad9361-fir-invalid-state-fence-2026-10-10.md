# AD9361 FIR partial-write validity fence — 2026-10-10

`ad9361_load_fir_filter_coef()` writes coefficient RAM sequentially. On an SPI error after coefficient writes begin, cleanup restores the FIR clock/enable fields and ENSM state but cannot restore the prior coefficient image. The public RX and TX FIR setters correctly leave `phy->fir_config_valid` false after the failed update. Before this change, RX transition begin did not inspect that flag, and the TX RFIC certificate considered only RFPLL, ENSM, BBPLL, and calibration status. A later transition could therefore certify samples or TX admission while the filter state was known invalid.

libbladeRF now rejects RX transition begin while the host AD9361 PHY is unavailable, its overall FIR clock/bandwidth validation is false, or the required coefficient lane masks are incomplete. The TX RFIC observation is explicitly invalid when hardware status reads succeed but the shared FIR configuration flag is false, so the existing fail-closed TX path emits the invalid-state event and aborts admission. no-OS tracks coefficient validity separately for RX1, RX2, TX1, and TX2; a partial failure clears the whole affected direction mask because its gain/decimation controls are shared, and recovery of the opposite direction cannot restore the aggregate flag. On dual-channel devices both lanes in both directions must be reprogrammed successfully before the flag becomes valid. The pure transition-policy source regression covers missing PHY, incomplete RX/TX lane masks, failed overall validation, single-channel masks, and invalid FIR state in TX observations.

Validation: `git diff --check` passed. The source regression was not built or run, and no library/FPGA/firmware build was started because the full RX+TX audit remains open. This closes certificate admission for the known invalid FIR state; it does not restore the old coefficient RAM image after an SPI error, and rollback-failure hardware qualification remains open. no-OS commit `02b04112e`; bladeRF commits `eef442f7`, `2079e5d5`.
